# Трекер привычек в Telegram

Telegram-бот для трекинга групповых привычек + Mini App-админка. Next.js (App Router) на
Vercel, Postgres через Neon, бот на `grammy`. Вся доменная логика — в `lib/`, независимо
от Next и Telegram; роуты — тонкие обёртки «проверил доступ → вызвал функцию → отдал JSON».

## Переменные окружения

| Имя | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота от BotFather |
| `DATABASE_URL` | строка подключения Neon (ставится Marketplace-интеграцией) |
| `ADMIN_IDS` | Telegram user id админов через запятую |
| `TZ` | IANA-зона, например `Asia/Almaty`; **при её смене правится и cron-выражения в `vercel.json`** |
| `WEBHOOK_SECRET` | секрет для `setWebhook(secret_token)` |
| `SETUP_SECRET` | ключ для вызова `/api/setup` |
| `CRON_SECRET` | Vercel сам шлёт его роутам крона в `Authorization: Bearer` |
| `APP_URL` | базовый URL для кнопки Mini App, например `https://telegram-trecker-ai-bot.vercel.app` |
| `DEV_ADMIN_ID` | только локально: пропуск проверки подписи `initData`, когда `NODE_ENV !== 'production'` |

`WEBHOOK_SECRET`, `SETUP_SECRET` и `CRON_SECRET` — любые случайные строки, например
`openssl rand -hex 16`.

Локальный `.env` для разработки использует эти же имена (в него же добавляется
`DEV_ADMIN_ID`) — если у вас остался старый файл со строчными `bot_token`/`admin_id`,
переименуйте их в `BOT_TOKEN`/`ADMIN_IDS`.

## Локальный запуск

```bash
npm install
npm test              # vitest, слой данных — PGlite, сеть не нужна
npx tsc --noEmit
npm run build
```

Next-приложение (Mini App-админка):

```bash
npm run dev
```

Бот — отдельным процессом, на long polling, без вебхука и туннелей (использует тот же
`lib/bot.ts`, что и продакшен-вебхук):

```bash
npm run bot
```

Роль админа в Mini App при локальном запуске даёт `DEV_ADMIN_ID` — он выключает проверку
подписи `initData` (эта ветка мертва в продакшене, `NODE_ENV === 'production'`).

## Развёртывание

Проект уже привязан к репозиторию в Vercel, деплой идёт из GitHub: пуш в `main` собирает
продакшен. CLI нужен только для переменных окружения (или задайте их в веб-интерфейсе
проекта).

1. Neon подключена как Marketplace-интеграция проекта — `DATABASE_URL` проставляется сам.
2. Заданы переменные окружения проекта (Production) — весь список из таблицы выше, кроме
   `DEV_ADMIN_ID` (он нужен только для локальной разработки).
3. Слияние ветки в `main` — Vercel соберёт продакшен сам.
4. `GET https://<домен>/api/setup?key=<SETUP_SECRET>` — миграции (`CREATE TABLE IF NOT
   EXISTS`), `setWebhook` с секретом, кнопка Mini App в меню бота. Идемпотентно,
   вызывается после каждого деплоя, меняющего схему.
5. Добавить бота в чат каждой группы и написать там `/bind`.
6. Проверить в Telegram: `/start` → имя → админ получает уведомление → назначить группы
   в Mini App → трекеры появились в меню.

## Расписания (`vercel.json`)

```json
{ "crons": [
  { "path": "/api/cron/reminder", "schedule": "0 16 * * *" },
  { "path": "/api/cron/weekly",   "schedule": "0 15 * * 0" }
]}
```

Выражения — **в UTC**, не в `TZ` проекта. Для `Asia/Almaty` (UTC+5): `0 16 * * *` — это
21:00 по местному времени; `0 15 * * 0` — воскресенье, 20:00 по местному. При смене `TZ`
правьте оба выражения вручную — отдельной переменной со временем нет, расписание в
`vercel.json` и есть единственный источник истины.

Обе задачи укладываются в лимит тарифа Hobby (не чаще раза в сутки на задачу) и
срабатывают с точностью ±59 минут: «21:00» реально означает «где-то между 21:00 и
21:59».

Оба роута требуют заголовок `Authorization: Bearer <CRON_SECRET>` (Vercel подставляет
его сам, когда переменная задана в проекте) — вызов без него или с чужим значением
получает 401.

Крон подхватывается **только на продакшен-деплое** — в preview-деплоях расписания из
`vercel.json` не запускаются, это ожидаемое поведение Vercel.
