# Трекер привычек в Telegram — дизайн

Дата: 2026-09-10

## 1. Задача

Закрытый трекер привычек для небольшого круга людей. Админ выдаёт доступ и создаёт
трекеры («прочитать 1 страницу»). Участник открывает бота, видит трекеры и одним тапом
отмечает выполнение за сегодня; повторный тап снимает отметку. Админ смотрит
статистику: кто что сделал сегодня, сколько за месяц, текущая серия, число пропусков.

Ограничения: бесплатно, быстро, без постоянного сервера, хостинг — Vercel.

## 2. Решения, принятые на брейншторме

| Вопрос | Решение |
|---|---|
| Связь трекеров и людей | Трекеры общие: созданный трекер виден всем допущенным |
| «Сегодня» | Один часовой пояс для всех, `TZ` из env; дата дня считается в SQL |
| Начало отсчёта пропусков | `max(users.allowed_at::date, trackers.created_at::date)` по паре (человек, трекер) |
| Выдача доступа | Заявка → одобрение: `/start` создаёт заявку, админ одобряет кнопкой |
| Удаление трекера | Мягкое: `archived_at`, история отметок сохраняется |
| Хранилище | Neon Postgres через Vercel Marketplace, драйвер `@neondatabase/serverless` (HTTP) |
| Фреймворк | grammY, режим webhook |

Сознательно не делаем: напоминания по расписанию, отметки задним числом,
редактирование текста трекера, экспорт, персональные трекеры, счётчики (больше одной
отметки в день).

## 3. Архитектура

Одна serverless-функция Vercel принимает вебхук Telegram, обрабатывает апдейт через
grammY и пишет в Neon Postgres. Отдельного фронта нет: отметки, администрирование
и статистика — внутри бота.

```
package.json            type: module; deps: grammy, @neondatabase/serverless; dev: vitest, pglite
api/bot.js              вебхук: проверка секрета → дедуп update_id → grammY
api/setup.js            миграции + setWebhook, защищён SETUP_SECRET
lib/config.js           разбор переменных окружения
lib/db.js               подключение (Neon + ретрай), миграции, «сегодня» в TZ
lib/users.js            заявки, allow/deny, список участников
lib/trackers.js         трекеры: добавить / список / архив
lib/checkins.js         тоггл отметки, состояние за сегодня, дедуп update_id
lib/stats.js            SQL: сегодня, месяц, серия, пропуски
lib/text.js             имена, дата по-русски, обрезка до лимита Telegram
lib/menu.js             сборка inline-клавиатуры трекеров
lib/bot.js              сборка бота: bot.catch, админ-композер, хендлеры
lib/handlers/user.js    /start, тапы по трекерам
lib/handlers/admin.js   доступ, трекеры, /stats
dev.js                  локальный запуск того же бота на long polling
```

Слой данных работает через один интерфейс `q(text, params) → rows`: в проде его
даёт Neon, в тестах — PGlite (Postgres в WASM, без сети и секретов).

`api/bot.js` — тонкая точка входа. Вся логика в `lib/`, чтобы `stats.js` и тоггл
тестировались без Telegram и без Vercel.

### Переменные окружения

| Имя | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота от BotFather |
| `DATABASE_URL` | строка подключения Neon (ставится Marketplace-интеграцией) |
| `ADMIN_IDS` | Telegram user id админов через запятую |
| `TZ` | IANA-зона, например `Asia/Almaty` |
| `WEBHOOK_SECRET` | секрет для `setWebhook(secret_token)`; проверяется в заголовке |
| `SETUP_SECRET` | ключ для вызова `/api/setup` |

## 4. Данные

```sql
CREATE TABLE IF NOT EXISTS users (
  id          bigint PRIMARY KEY,          -- telegram user id
  username    text,
  first_name  text,
  status      text NOT NULL,               -- 'pending' | 'allowed' | 'denied'
  created_at  timestamptz NOT NULL DEFAULT now(),
  allowed_at  timestamptz                  -- первое одобрение; при deny не стирается
);

CREATE TABLE IF NOT EXISTS trackers (
  id          serial PRIMARY KEY,
  title       text NOT NULL,
  created_at  timestamptz NOT NULL DEFAULT now(),
  archived_at timestamptz
);

CREATE TABLE IF NOT EXISTS checkins (
  user_id     bigint NOT NULL REFERENCES users(id),
  tracker_id  int    NOT NULL REFERENCES trackers(id),
  day         date   NOT NULL,
  created_at  timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, tracker_id, day)
);

CREATE TABLE IF NOT EXISTS processed (
  update_id   bigint PRIMARY KEY,
  at          timestamptz NOT NULL DEFAULT now()
);
```

Правила:

- **Сегодня** — `(now() AT TIME ZONE $TZ)::date`, вычисляется в SQL, один источник истины.
- **Отметка** — наличие строки в `checkins`. Тоггл: `DELETE … RETURNING`; если строка
  вернулась — отметка снята, иначе `INSERT … ON CONFLICT DO NOTHING`. Операция
  идемпотентна по построению; никаких счётчиков и состояния в сообщении.
- **`allowed_at`** ставится при первом переходе в `allowed` и больше не меняется,
  чтобы повторный доступ после `deny` не обнулял начало отсчёта.
- **Дедуп апдейтов.** Telegram повторяет апдейт, если вебхук не ответил 200 (таймаут,
  холодный старт). Для тоггла повтор снял бы только что поставленную отметку. Поэтому
  первый шаг обработчика — `INSERT INTO processed … ON CONFLICT DO NOTHING`; при
  конфликте отвечаем 200 и выходим. Строки старше суток удаляются тем же запросом.
- **Админы** из `ADMIN_IDS` считаются `allowed` без заявки; при первом обращении
  строка в `users` создаётся с `status='allowed'`, `allowed_at=now()`.

## 5. Статистика (`lib/stats.js`)

Для пары (человек, трекер):

- **start** = `max(allowed_at::date, trackers.created_at::date)`.
- **сегодня** — есть ли строка с `day = today`.
- **за месяц** — `N/M`: N — отметок с `date_trunc('month', today)` по `today`
  включительно; M — число дней от `max(start, начало месяца)` по `today` включительно.
- **серия** — длина непрерывного хвоста дней, заканчивающегося сегодня или вчера.
  Сегодняшний день без отметки серию не рвёт. Считается через
  `day - row_number() OVER (ORDER BY day)` и группировку.
- **пропуски** — дней от start по **вчера** включительно минус отметки за тот же
  период. Сегодня в пропуски не входит: день ещё не кончился. Если start > вчера,
  пропусков 0.

`/stats` без аргумента — срез за сегодня: по каждому активному трекеру список
отметившихся и не отметившихся. `/stats <user_id>` — карточка человека по каждому
активному трекеру: `сегодня ✅ · месяц 12/23 · серия 4 · пропуски 11`.

## 6. Поведение бота

### Участник

`/start` по `status`:

| Состояние | Ответ |
|---|---|
| записи нет | создать `pending`; «Заявка отправлена»; админам сообщение «Имя (@username, id) просит доступ» с кнопками *Пустить / Отказать* |
| `pending` | «Заявка на рассмотрении» (админов повторно не уведомляем) |
| `denied` | «Нет доступа» (новая заявка не создаётся) |
| `allowed` | меню |

Меню — одно сообщение: в шапке дата (`Сегодня, 10 сентября`), ниже по кнопке на
активный трекер: `✅ Прочитать 1 страницу` / `⬜️ Прочитать 1 страницу`.
`callback_data` = `t:<tracker_id>`.

Тап: сервер тогглит запись за **свой** сегодняшний день, перерисовывает всю
клавиатуру (`editMessageReplyMarkup`) по актуальному состоянию, отвечает
`answerCallbackQuery` — «Отмечено» / «Снято». Перерисовка целиком закрывает случай
вчерашнего меню, оставшегося в чате: тап применяется к сегодня, и сообщение сразу
показывает сегодня. Тап по архивированному трекеру → «Трекер удалён» и перерисовка.

При одобрении заявки участнику приходит «Доступ выдан» и меню.

### Админ

- Доступ: `/users` — заявки и участники, у каждого кнопки (*Пустить / Отказать* для
  pending, *Отключить* для allowed, *Пустить* для denied). `/allow <id>`, `/deny <id>`
  — запасной текстовый путь.
- Трекеры: `/add <текст>` создаёт; `/list` показывает активные с id; `/del` без
  аргумента показывает кнопки по трекерам, тап → подтверждение → `archived_at = now()`.
  Аргумент-id не основной путь: опечатка молча архивирует не тот трекер.
- Статистика: `/stats`, `/stats <id>` — см. §5.
- `/allow <id>` для человека, которого ещё нет в `users`, создаёт запись `allowed`
  сразу — так можно пустить участника заранее, зная его id.
- Любой другой текст, а также админская команда от не-админа, обрабатывается как
  `/start`: участник получает меню или сообщение по статусу заявки.

Любой список режется по лимиту Telegram 4096 символов с хвостом «…и ещё N».

## 7. Надёжность и безопасность

- **Секрет вебхука.** `setWebhook` вызывается с `secret_token = WEBHOOK_SECRET`.
  `api/bot.js` первым делом сверяет заголовок `X-Telegram-Bot-Api-Secret-Token`;
  несовпадение → 401. Без этого любой, узнав URL, отправит апдейт с
  `from.id = ADMIN_ID`.
- **`/api/setup`** принимает только `?key=SETUP_SECRET`; иначе 401.
- **Ошибки.** Обработчик всегда отвечает 200, даже при исключении — `processed`
  записан до работы, ретрай Telegram всё равно был бы проглочен и лишь задерживал бы
  очередь. `bot.catch` пишет `console.error` (видно в `vercel logs`) и отвечает
  пользователю «Что-то пошло не так, попробуйте ещё раз»; операции идемпотентны,
  повторный тап безопасен.
- **Neon после простоя.** Один повтор запроса при ошибке соединения.
- **Vercel.** Функции Node.js (Fluid Compute), без `vercel.json`. Таймаут по умолчанию
  достаточен.

## 8. Тестирование

vitest. Тесты пишутся до кода.

- `lib/stats.js` против PGlite (тот же SQL, что в Neon; дата «сегодня» в тестах
  фиксируется параметром): серия при отметке вчера, но не сегодня; разрыв в
  середине; start позже создания трекера; переход через границу месяца; человек
  без отметок; архивированный трекер не попадает в выдачу.
- Вычисление «сегодня» на границе суток в заданном `TZ`.
- Тоггл: два вызова подряд возвращают исходное состояние; повторный `update_id`
  ничего не делает.
- Проверка секрета вебхука: без заголовка / с неверным — 401, апдейт не обработан.

Ручная проверка — `node --env-file=.env dev.js`: тот же бот на long polling,
без деплоя, туннелей и dotenv (Node ≥ 20 читает `.env` сам).

## 9. Развёртывание

1. `npm i -g vercel`, `vercel link`.
2. Neon — как Marketplace-интеграция Vercel (`vercel integration`): `DATABASE_URL`
   проставляется в проект сам.
3. `vercel env add` для `BOT_TOKEN`, `ADMIN_IDS`, `TZ`, `WEBHOOK_SECRET`, `SETUP_SECRET`.
4. `vercel deploy --prod`.
5. `GET https://<домен>/api/setup?key=<SETUP_SECRET>` — создаёт таблицы
   (`CREATE TABLE IF NOT EXISTS`) и ставит вебхук. Идемпотентно, можно звать после
   каждого деплоя.
