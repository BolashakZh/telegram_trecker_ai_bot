# Трекер привычек в Telegram: группы, трекеры, админка — дизайн

Дата: 2026-09-10 (заменяет первую версию дизайна, где трекеры были общими для всех,
а администрирование жило целиком в боте; код по той версии не писался)

## 1. Задача

Закрытый трекер привычек для нескольких групп людей.

- Люди делятся на **группы** (сейчас их три). У группы свой набор **трекеров**.
- Один человек может состоять в нескольких группах, и один трекер может входить в
  несколько групп. Поэтому трекеры — отдельный каталог, группы — отдельная сущность,
  а связка между ними — третья.
- Трекер бывает двух типов: **галочка** («Зарядка») и **число** («Страницы, цель 10»).
- Отмечается каждый сам, в личном чате с ботом, за сегодняшний день.
- Вечером бот пишет тем, у кого остались невыполненные трекеры.
- По воскресеньям бот публикует итоги недели в чат каждой группы.
- Человек в любой момент смотрит свою статистику и сводку по своим группам.
- Админ работает в **Mini App**: назначает людей в группы, ведёт группы и каталог
  трекеров, правит имена, смотрит дашборд.

Ограничения: бесплатный тариф Vercel, без постоянного сервера.

## 2. Решения, принятые на брейншторме

| Вопрос | Решение |
|---|---|
| Один трекер в двух группах у одного человека | Отметка одна: ключ `(человек, трекер, день)`; засчитывается во все группы |
| Числовой трекер | Цель и единица живут у трекера (одинаковы во всех группах); выполнено = `value >= target` |
| Описание трекера | Необязательное поле до 200 символов: короткое название идёт на кнопку, описание объясняет, о чём речь. Видно на экране «ℹ️ Трекеры» и в запросе числа |
| Группа и Telegram-чат | Один к одному: у группы свой чат, отчёт уходит только туда |
| Админка | Mini App внутри Telegram, всё управление там; в боте остаются только уведомление о новичке и `/bind` |
| Напоминания | Одно время для всех, задаётся cron-выражением |
| Доступ | Членство в группе и есть доступ; отдельного `allowed/denied` нет |
| Что видит участник | Свою статистику и сводку по своим группам |
| Отметки задним числом | Нет, только текущий день |
| Периодичность | Все трекеры ежедневные |
| Имя человека | Спрашивается при `/start`; админ может переопределить и заблокировать смену |
| Стек | Next.js (App Router) + React + TypeScript, Tailwind; grammY; Neon Postgres |
| Язык | Всё, что бот пишет участникам (личка, чаты групп, даты), — на казахском. Админка, ошибки валидации, уведомления админам, ответы на `/bind` и документация — на русском |
| Планировщик | Vercel Cron на Hobby: раз в сутки, точность ±59 минут |
| Свежесть `initData` | 24 часа |

Сознательно не делаем: недельные цели («3 раза в неделю»), трекеры по дням недели,
персональные времена напоминаний, экспорт, графики-библиотеки, аудит действий админа,
назначение группы человеку, который ещё не писал боту.

## 3. Архитектура

Один Next.js-проект на Vercel. Вся доменная логика — в `lib/`, независимо от Next,
Telegram и Vercel; роуты — тонкие обёртки «проверил доступ → вызвал функцию → отдал
JSON». Благодаря этому статистика и отчёты тестируются на PGlite без сети и секретов.

```
app/
  api/telegram/route.ts        вебхук: секрет → дедуп update_id → grammY
  api/setup/route.ts           миграции + setWebhook + setChatMenuButton (по SETUP_SECRET)
  api/cron/reminder/route.ts   вечернее напоминание
  api/cron/weekly/route.ts     воскресный отчёт в чаты групп
  api/admin/bootstrap/route.ts всё для первого экрана одним запросом
  api/admin/users/route.ts     имя, членство в группах
  api/admin/groups/route.ts    CRUD групп, привязка трекеров, отвязка чата
  api/admin/trackers/route.ts  CRUD каталога трекеров
  api/admin/stats/route.ts     данные дашборда по группе и периоду
  admin/page.tsx               Mini App: четыре вкладки
lib/
  db.ts        q(text, params) → rows; Neon в проде, PGlite в тестах; today(tz)
  auth.ts      проверка initData (HMAC-SHA256, auth_date), requireAdmin
  users.ts     регистрация, имя, членства
  groups.ts    группы, привязка чата, состав
  trackers.ts  каталог, связь с группами
  entries.ts   тоггл галочки, запись числа, состояние за сегодня, claimUpdate
  stats.ts     все SQL-агрегаты: личные, групповые, недельные
  report.ts    тексты напоминания и воскресного отчёта
  menu.ts      клавиатуры бота
  text.ts      personName, даты по-русски, бары, моноширинные таблицы, обрезка
  validate.ts  ручная валидация входа админских ручек
  bot.ts       сборка бота, bot.catch
  handlers/user.ts   /start, имя, тапы, статистика, сводка группы
  handlers/admin.ts  уведомление о новичке, /bind
scripts/dev-bot.ts   локальный запуск того же бота на long polling
```

Runtime всех роутов — Node.js (не Edge): `grammy` и HTTP-драйвер Neon там ведут себя
предсказуемо.

### Переменные окружения

| Имя | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота от BotFather |
| `DATABASE_URL` | строка подключения Neon (ставится Marketplace-интеграцией) |
| `ADMIN_IDS` | Telegram user id админов через запятую |
| `APP_TZ` | IANA-зона, например `Asia/Almaty`; имя `TZ` зарезервировано Vercel. **При её смене правится и cron-выражение в `vercel.json`** |
| `WEBHOOK_SECRET` | секрет для `setWebhook(secret_token)` |
| `SETUP_SECRET` | ключ для вызова `/api/setup` |
| `CRON_SECRET` | Vercel сам шлёт его роутам крона в `Authorization: Bearer` |
| `APP_URL` | базовый URL для кнопки Mini App |
| `DEV_ADMIN_ID` | только локально: пропуск проверки подписи при `NODE_ENV !== 'production'` |

## 4. Данные

```sql
CREATE TABLE IF NOT EXISTS users (
  id           bigint PRIMARY KEY,           -- telegram user id
  username     text,
  first_name   text,
  display_name text,                          -- то, что видно везде
  name_locked  boolean NOT NULL DEFAULT false,-- имя задал админ
  created_at   timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS groups (
  id          serial PRIMARY KEY,
  title       text NOT NULL,
  chat_id     bigint UNIQUE,                  -- чат группы, привязывается /bind
  created_at  timestamptz NOT NULL DEFAULT now(),
  archived_at timestamptz
);

CREATE TABLE IF NOT EXISTS trackers (
  id          serial PRIMARY KEY,
  title       text NOT NULL,                  -- короткое имя для кнопки: «Книга»
  description text,                           -- зачем он: «читаем про психологию, 10 стр. в день»
  kind        text NOT NULL,                  -- 'check' | 'number'
  target      numeric NOT NULL DEFAULT 1,     -- у 'check' всегда 1
  unit        text,                           -- 'стр.', 'км' — только у 'number'
  created_at  timestamptz NOT NULL DEFAULT now(),
  archived_at timestamptz
);

CREATE TABLE IF NOT EXISTS group_trackers (
  group_id   int NOT NULL REFERENCES groups(id),
  tracker_id int NOT NULL REFERENCES trackers(id),
  linked_at  timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (group_id, tracker_id)
);

CREATE TABLE IF NOT EXISTS memberships (
  user_id   bigint NOT NULL REFERENCES users(id),
  group_id  int    NOT NULL REFERENCES groups(id),
  joined_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, group_id)
);

CREATE TABLE IF NOT EXISTS entries (
  user_id    bigint  NOT NULL REFERENCES users(id),
  tracker_id int     NOT NULL REFERENCES trackers(id),
  day        date    NOT NULL,
  value      numeric NOT NULL DEFAULT 1,
  created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, tracker_id, day)
);

CREATE TABLE IF NOT EXISTS pending_input (
  user_id    bigint PRIMARY KEY REFERENCES users(id),
  tracker_id int NOT NULL REFERENCES trackers(id),
  at         timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS processed (
  update_id bigint PRIMARY KEY,
  at        timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS sent_log (
  kind text NOT NULL,                          -- 'remind' | 'weekly'
  key  text NOT NULL,                          -- '2026-09-10:12345' | '2026-09-07:7'
  at   timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (kind, key)
);
```

Правила, на которых держится модель:

- **Одна формула выполнения.** `done = entries.value >= trackers.target`. Галочка —
  это `target = 1, value = 1`; числовой трекер — `target = 10, value = 12`. Весь SQL
  статистики одинаков для обоих типов, ветвлений по `kind` в агрегатах нет.
- **Отметка не знает про группы.** `entries` ссылается на трекер, а не на пару
  группа-трекер. Человек в трёх группах с общим «Чтением» отмечает один раз, и это
  видно во всех трёх сводках. В меню такой трекер показан один раз.
- **Членство = доступ.** Трекеры человека — активные трекеры всех его групп через
  `memberships → group_trackers`, с дедупликацией. Нет членств — нет доступа. Убрали
  из всех групп — доступ закрыт, история отметок цела.
- **Начало отсчёта** по паре (человек, трекер):
  `min по группам от max(memberships.joined_at, group_trackers.linked_at, trackers.created_at)::date`.
  Человека, добавленного вчера, не наказываем пропусками за январь.
- **Сегодня** — `(now() AT TIME ZONE $TZ)::date`, считается в SQL; функции получают
  `today` параметром, чтобы тесты фиксировали дату.
- **Мягкое удаление.** `archived_at` у групп и трекеров: пропадают из меню, из
  дашборда и из будущих отчётов, отметки в истории остаются.
- **Дедуп апдейтов.** Первый шаг обработчика вебхука — `INSERT INTO processed …
  ON CONFLICT DO NOTHING`; при конфликте отвечаем 200 и выходим, иначе повтор
  апдейта от Telegram снял бы только что поставленную отметку. Строки старше суток
  удаляются тем же запросом.
- **Дедуп рассылок.** `sent_log` заполняется **до** отправки; не вставилось — значит
  уже слали, пропускаем.
- **Даты через границу SQL ↔ JS** ходят только строками `YYYY-MM-DD`; агрегаты
  кастуются `::int` / `::numeric` явно.

## 5. Статистика (`lib/stats.ts`)

Все расчёты — в SQL, один источник истины для бота, отчётов и дашборда.

Для пары (человек, трекер):

- **start** — начало отсчёта по правилу из §4.
- **сегодня** — есть ли строка `entries` за `today` с `value >= target`.
- **процент за период** — выполненные дни ÷ ожидаемые дни, где ожидаемые считаются
  от `max(start, начало периода)` по `today` включительно.
- **серия** — длина непрерывного хвоста выполненных дней, заканчивающегося сегодня
  или вчера; сегодняшний день без отметки серию не рвёт. Считается через
  `day - row_number() OVER (ORDER BY day)` и группировку.
- **пропуски** — дней от `start` по **вчера** включительно минус выполненные дни за
  тот же период; сегодня в пропуски не входит, день ещё не кончился.
- **сумма и цель за период** — только для `kind = 'number'`: `sum(value)` и
  `target × ожидаемые дни`.

Для группы за период (неделя = ISO пн–вс через `date_trunc('week', …)`, месяц —
календарный):

- **процент участника** — выполненные пары (трекер × день) ÷ ожидаемые, по трекерам
  этой группы, с учётом `start` каждой пары;
- **процент группы** — среднее по участникам;
- **процент по трекеру** — по всем участникам группы;
- **карта дней** — процент выполнения по каждому дню периода на участника (для
  тепловой карты в дашборде);
- **кто сегодня не отметился** — список пар (человек, трекер).

## 6. Бот

### Онбординг и имя

`/start` от незнакомого человека: «Здравствуйте! Как вас зовут? Напишите имя и
фамилию — так в группе поймут, кто вы.» Пока `display_name IS NULL`, любое текстовое
сообщение считается ответом: отдельного состояния не нужно. Проверка: обрезаем
пробелы, схлопываем повторы, 2–40 символов, есть хотя бы одна буква. Не прошло —
«Напишите имя буквами, например: Айгуль Смагулова».

Уведомление админам уходит **после** ввода имени: «Новый участник: Айгуль Смагулова
(@aigul, 12345)» с кнопкой ⚙️ Открыть админку. Иначе админ увидел бы в списке
человека с ником вроде «Человек-паук» и не понял, кому назначать группы.

Смена имени участником — `/name Айгуль Смагулова` или кнопка «✏️ Сменить имя» на
экране статистики; при `name_locked = true` — «Ваше имя задал администратор,
напишите ему», иначе правка админа откатывалась бы за минуту.

Везде, где показывается человек, используется `personName(user)`:
`display_name` → `first_name` → `@username` → `id`. Fallback нужен, потому что админы
из `ADMIN_IDS` попадают в базу без онбординга.

`first_name` и `username` обновляются при каждом апдейте, но показываются только в
админке рядом с именем (`Айгуль Смагулова · @aigul · 12345`).

### Главный экран

Одно сообщение, которое перерисовывается на месте:

```
Сегодня, четверг 10 сентября
Выполнено 3 из 5  ▰▰▰▱▱

✅ Зарядка
⬜️ Медитация
✅ Страницы  12/10
⬜️ Пробежка  0/5 км
✅ Без сахара

📈 Моя статистика │ 👥 Группа │ ℹ️ Трекеры
```

Порядок трекеров стабильный (по id), чтобы кнопка не прыгала под пальцем.
`callback_data`: `t:<tracker_id>` — тап по трекеру, `s:me` — статистика,
`s:g:<group_id>` — сводка группы, `s:info` — описания трекеров.

**ℹ️ Трекеры** — экран с описаниями: по строке на активный трекер, `Название — описание`
(для числового ещё цель и единица). Трекер без описания показывает только название.
Это единственное место, где описание видно целиком: на кнопку оно не влезает, а без
него человек не понимает, что за «Книга» и сколько именно от него хотят.

**Тап по галочке** — тоггл `entries` за сегодня (`DELETE … RETURNING`, иначе
`INSERT`), перерисовка всей клавиатуры по свежему состоянию, `answerCallbackQuery`
«Отмечено ✅» / «Снято». Перерисовка целиком закрывает случай вчерашнего меню,
оставшегося в чате: тап применяется к сегодня, и сообщение сразу показывает сегодня.

**Тап по числовому** — бот отправляет сообщение «Книга — читаем про психологию, 10 стр.
в день. Сколько сегодня? Пришлите число» (описание подставляется, если оно есть) с
`ForceReply` и пишет строку в `pending_input` (PK по `user_id`, поэтому «начал вводить
одно, передумал, ткнул другое» разрешается само собой). Следующее сообщение парсится
как число: `12`, `12.5`, `12,5` принимаются; мусор → «Нужно число, например 12», при
этом состояние сохраняется. `0` эквивалентен снятию отметки: строка удаляется. После
записи — «Записано: 12 стр. ✅ (цель 10)» и перерисовка главного меню. Повторный тап
по заполненному числовому запускает тот же поток, значение перезаписывается.
`pending_input` старше 15 минут игнорируется: текст через час — это не ввод числа,
показываем меню.

Тап по трекеру, который успели заархивировать или отвязать от всех групп человека →
«Трекер больше не активен» и перерисовка.

### Статистика участника

`📈 Моя статистика` — моноширинно, по каждому активному трекеру:

```
Зарядка      неделя ▰▰▰▰▰▱▱ 5/7   серия 4   месяц 68%
Страницы     неделя ▰▰▰▱▱▱▱ 3/7   серия 0   месяц 41%
             за неделю 47 стр. (цель 70)
```

`👥 Группа` — если групп несколько, сначала кнопки с названиями, затем сводка за
текущую неделю:

```
Группа «Утро», неделя 7–13 сентября

Айгуль    ▰▰▰▰▰▰▱ 86%
Данияр    ▰▰▰▰▱▱▱ 57%
Вы        ▰▰▰▱▱▱▱ 43%

Сегодня не отметились: Данияр — Медитация, Пробежка
```

Человек без членств получает «Доступ пока не выдан, админ уже уведомлён» и ничего
больше. Когда админ назначает его в группу, бот сразу пишет ему «Вам открыт доступ —
группа «…»» и показывает главный экран: нажимать `/start` заново не нужно. Сообщение
уходит только при новом членстве; снятие из группы проходит молча. Любой неожиданный текст от человека с именем и группами открывает главный
экран.

### Админ в боте

Ровно две вещи, остальное — в Mini App:

- уведомление о новом участнике с кнопкой ⚙️ Открыть админку (`web_app`);
- `/bind` в чате группы: бот отвечает списком групп кнопками, тап привязывает
  `chat_id` к выбранной группе. Нажавший проверяется по `ADMIN_IDS`. Так чат
  настраивается без копирования отрицательных id руками.

Любой список режется по лимиту Telegram 4096 символов с хвостом «…и ещё N».

## 7. Mini App: админка

### Доступ

Страница `/admin` публична — Vercel отдаёт HTML кому угодно, но без `initData` от
Telegram первый же запрос к API вернёт 401 и человек увидит «Откройте админку через
бота».

Каждый запрос к `/api/admin/*` шлёт `initData` в заголовке `X-Init-Data`. Сервер:

1. проверяет подпись — `secret = HMAC_SHA256("WebAppData", BOT_TOKEN)`, затем `hash`
   по отсортированной `data_check_string`; подделать без токена бота нельзя;
2. проверяет `auth_date` — не старше **24 часов**; иначе «сессия истекла, откройте
   заново из бота»;
3. проверяет `user.id ∈ ADMIN_IDS`.

Проверку делает каждый роут через `requireAdmin(req)`. Спрятанная на фронте кнопка
защитой не считается: участник с валидной подписью, но не из `ADMIN_IDS`, получает
401 на шаге 3. `ADMIN_IDS` в браузер не уезжает.

### Экраны

Четыре вкладки внизу.

**Люди.** Карточки; сверху те, у кого ещё нет групп, с меткой «новый». В карточке:
имя (правится по тапу на карандаш), под ним `@username · id`, ниже чипсы всех групп —
тап включает или выключает членство, без формы и кнопки «сохранить»; при новом
назначении бот сам уведомляет человека (см. §6). Отдельная
галочка «разрешить менять имя самому» снимает `name_locked`; любая правка имени
админом ставит его обратно.

**Группы.** Карточка на группу: название, статус чата («Чат привязан» / «Не привязан
— напишите `/bind` в чате группы»), число участников. Внутри: мультивыбор трекеров из
каталога, состав, переименование, архивирование, отвязка чата.

**Трекеры.** Каталог, независимый от групп: название (короткое, идёт на кнопку),
описание (до 200 символов, необязательное), тип, для числового — цель и единица. Рядом —
в каких группах используется, чтобы было видно, что «Чтение» одно на три группы, а не
три разных. Архивирование мягкое.

**Дашборд.** Группа + период (неделя / месяц):

```
Утро · 7–13 сентября                     общий 64%

              Пн Вт Ср Чт Пт Сб Вс    %
Айгуль        ██ ██ ██ ██ ██ ░░ ░░   71
Данияр        ██ ██ ░░ ██ ░░ ░░ ░░   43
Ержан         ██ ██ ██ ██ ██ ██ ██  100

По трекерам:  Зарядка 76% · Чтение 52% · Медитация 61%
Чтение: 218 стр. за неделю (цель 210)
```

Тепловая карта — `div` с цветом по проценту дня; графических библиотек нет.

### Техника фронта

Tailwind (идёт с `create-next-app`), без shadcn/radix — компонентов немного, а
зависимостей они тянут много. Тема берётся из `themeParams` Telegram, поэтому админка
автоматически светлая или тёмная. Скрипт `telegram-web-app.js` подключается тегом,
типы — dev-зависимостью; SDK-обёртки не нужны.

### API

`GET /api/admin/bootstrap` отдаёт всё для стартового рендера (группы, каталог
трекеров, люди с членствами) — страница открывается одним запросом, без каскада.

Мутации — короткие `POST` с JSON, каждая возвращает обновлённый кусок; UI обновляется
оптимистично и подтягивает `bootstrap` при расхождении:

| Ручка | Тело |
|---|---|
| `/api/admin/users` | `{ action: 'rename', userId, displayName }` \| `{ action: 'unlockName', userId }` \| `{ action: 'membership', userId, groupId, on }` |
| `/api/admin/groups` | `{ action: 'create' \| 'rename' \| 'archive' \| 'unbindChat' \| 'tracker', … }` |
| `/api/admin/trackers` | `{ action: 'create' \| 'update' \| 'archive', … }` |
| `/api/admin/stats` | `GET ?groupId=&period=week\|month` |

Ошибки — единый `{ error }` и HTTP 400/401/500; фронт показывает `WebApp.showAlert`.
Валидация на сервере ручная, в `lib/validate.ts`: длины, типы, «цель > 0 у числового»,
«нельзя привязать архивный трекер», «нельзя завести числовой трекер без единицы».
Zod ради шести полей не нужен.

## 8. Расписания

Расписание Vercel Cron задаётся **в UTC**. Для `Asia/Almaty` (UTC+5) «21:00 по
местному» — это `0 16 * * *`:

```json
{ "crons": [
  { "path": "/api/cron/reminder", "schedule": "0 16 * * *" },
  { "path": "/api/cron/weekly",   "schedule": "0 15 * * 0" }
]}
```

Обе задачи укладываются в Hobby (не чаще раза в сутки) и срабатывают с точностью
±59 минут: «21:00» реально означает «между 21:00 и 21:59». Отдельной переменной с
временем нет — время задаёт расписание, второй источник истины только путал бы. При
смене `TZ` правится и cron-выражение.

Оба роута требуют `Authorization: Bearer <CRON_SECRET>` (Vercel подставляет сам, если
переменная задана); чужой вызов получает 401.

**Напоминание.** Берём `today` в `TZ`, выбираем людей, у которых есть хотя бы один
активный трекер без выполнения за сегодня. Каждому — «Осталось на сегодня: 2 трекера»
и то же главное меню кнопками, чтобы отметить можно было прямо из напоминания. Перед
отправкой — `sent_log('remind', '<день>:<user_id>')`. Ошибка отправки (человек
заблокировал бота) логируется и не роняет рассылку остальным.

**Воскресный отчёт.** Для каждой группы с привязанным чатом — итоги недели пн–вс,
включая сегодня:

```
🏁 Утро · итоги недели 7–13 сентября

Ержан     ▰▰▰▰▰▰▰ 100%
Айгуль    ▰▰▰▰▰▱▱  71%
Данияр    ▰▰▰▱▱▱▱  43%

Группа в среднем: 71%
Зарядка 76% · Чтение 52% · Медитация 61%
Чтение: 218 стр. за неделю
```

Ключ идемпотентности — `sent_log('weekly', '<понедельник недели>:<group_id>')`.
Группа без чата пропускается с записью в лог. Таблица уходит в `<pre>`, чтобы столбцы
не разъезжались на телефонах.

## 9. Надёжность и безопасность

- **Секрет вебхука.** `setWebhook` вызывается с `secret_token = WEBHOOK_SECRET`;
  роут первым делом сверяет заголовок `X-Telegram-Bot-Api-Secret-Token`, несовпадение
  → 401. Без этого любой, узнав URL, отправил бы апдейт с `from.id` админа.
- **`/api/setup`** принимает только `?key=SETUP_SECRET`.
- **Ошибки вебхука.** Код ответа выбирается по причине сбоя, а не одинаково:
  - тело не разобралось или в нём нет числового `update_id` → **200**: повторять такой
    запрос бессмысленно, он не станет валиднее;
  - `claimUpdate` упал (база недоступна) → **500**: строка в `processed` не записана,
    ретрай Telegram — единственный шанс не потерять отметку человека;
  - исключение внутри `bot.handleUpdate` → **200**: `processed` уже записан, повтор всё
    равно будет проглочен и лишь задержит очередь.

  Каждая ветка пишет `console.error`. `bot.catch` дополнительно отвечает человеку
  «Что-то пошло не так, попробуйте ещё раз»; операции идемпотентны, повторный тап
  безопасен.
- **Neon после простоя.** Один повтор запроса при ошибке соединения.
- **Локальный обход подписи.** `DEV_ADMIN_ID` работает только при
  `NODE_ENV !== 'production'`; в проде ветка мертва и переменной там нет.

## 10. Тестирование

vitest, слой данных — PGlite (тот же SQL, что в Neon). Тесты пишутся до кода.

- статистика: процент с учётом даты вступления в группу и даты привязки трекера;
  серия (отметка вчера, но не сегодня; разрыв в середине); пропуски; границы недели и
  месяца; человек без отметок; архивный трекер исчезает из выдачи, но не из истории;
- человек в двух группах с общим трекером: одна отметка засчитывается в обеих
  сводках, в меню трекер показан один раз;
- числовой трекер: `value >= target` — выполнение, `0` — снятие, перезапись значения,
  дробные значения;
- тоггл галочки идемпотентен; повторный `update_id` не переворачивает отметку;
- вычисление «сегодня» на границе суток в заданном `TZ`;
- `initData`: валидная проходит, испорченный `hash` — 401, `auth_date` старше суток —
  401, валидная подпись не-админа — 401;
- рассылки: выборка «кому напоминать», текст отчёта на фикстуре, повторный запуск
  крона не шлёт второе сообщение, группа без чата пропускается;
- имя: валидация ввода, `name_locked` запрещает `/name`, `personName` и его fallback;
- вебхук: без заголовка секрета и с неверным — 401, апдейт не обработан.

React-компоненты тестами не покрываются: логика живёт в `lib/` и в API, страница —
тонкий слой. Проверяется руками в Telegram.

Локально: `npm run dev` поднимает Next; бот — `scripts/dev-bot.ts` на long polling
(тот же `lib/bot.ts`, без вебхука и туннелей). Mini App открывается в браузере, роль
админа даёт `DEV_ADMIN_ID`.

## 11. Развёртывание

1. `create-next-app` (TypeScript, Tailwind, App Router). Прод-зависимости: `grammy`,
   `@neondatabase/serverless`. Dev: `vitest`, `@electric-sql/pglite`, типы Telegram
   WebApp.
2. Neon — Marketplace-интеграция Vercel: `DATABASE_URL` проставляется сам.
3. `vercel env add` для `BOT_TOKEN`, `ADMIN_IDS`, `TZ`, `WEBHOOK_SECRET`,
   `SETUP_SECRET`, `CRON_SECRET`, `APP_URL`. Локальный `.env` переименовать под эти
   имена (сейчас там `bot_token`, `admin_id`).
4. `vercel.json` с двумя cron-задачами из §8.
5. `vercel deploy --prod`.
6. `GET https://<домен>/api/setup?key=<SETUP_SECRET>` — миграции
   (`CREATE TABLE IF NOT EXISTS`), `setWebhook` с секретом, `setChatMenuButton` с URL
   Mini App. Идемпотентно, можно звать после каждого деплоя.
7. Добавить бота в чат каждой группы и написать там `/bind`.
